# 四号/五号重复代码收敛计划

## 审计结果

2026-09-25 按相对路径、文件大小和 SHA-256 内容哈希审计：

- 完全相同文件共 146 个，约 997 KB。
- 其中 `backend/app` 下完全相同文件为 143 个。
- 其余 3 个为 `account_metrics.py`、`universes.json`、`v4_selection.py`。
- 完整清单见 `v4-v5-duplicate-audit-20260925.json`。

## 收敛原则

不在生产目录间建立符号链接，也不直接删除四号文件。两种做法都会让任一项目的修改隐式影响另一套实盘服务，并使独立回滚失效。

采用版本化公共包，按以下批次迁移：

1. 纯模型、schema、配置解析和无副作用工具。
2. 交易所客户端、订单 DTO 与执行端口。
3. API 通用端点和账户能力。
4. 经过行为回归测试覆盖的风控与退出规则。
5. vendor 参考实现最后处理，策略编排器不进入公共包。

四号和五号分别固定公共包版本。某一项目需要差异化时，在自身适配层实现，不复制整个公共模块。

## 删除门槛

每个迁移批次必须同时满足：

- 四号、五号各自语法检查和完整测试通过。
- 两套服务在影子环境完成一轮扫描。
- 两套生产服务重启后 `/health` 均为 `healthy`。
- Git 中存在可独立回滚的迁移提交和版本标签。

达到这些门槛前，重复清单只用于审计，不删除任何生产文件。
